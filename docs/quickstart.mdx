---
title: "Quickstart"
---

Get Kioku running locally in 5 minutes.

<Steps>
  <Step title="Prerequisites">
    - [Docker](https://docs.docker.com/get-docker/) with Compose v2
    - NVIDIA GPU + [nvidia-container-toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/) (for Ollama embeddings)
    - (Optional) Cloudflare Tunnel for public access
  </Step>

  <Step title="Clone and setup">
    ```bash
    git clone --recurse-submodules https://github.com/kioku-org/kioku.git
    cd kioku
    git submodule update --init --recursive
    cd deployment/docker

    cp .env.example .env
    ```
  </Step>

  <Step title="Configure environment">
    ```bash
    # Required — Hivemind secrets, Vexa admin token, dashboard secret
    $EDITOR .env

    # Optional — add API keys for integrations
    # OPENAI_API_KEY=...
    # ANTHROPIC_API_KEY=...
    # ZOOM_CLIENT_ID=...
    # ZOOM_CLIENT_SECRET=...
    ```
    See [Environment Variables](/deployment/environment-variables) for the required-vs-optional breakdown.
  </Step>

  <Step title="Start the stack">
    ```bash
    docker compose -f docker-compose.stateful.yml up -d
    ```

    Everything — Postgres, Qdrant, Redis, MinIO, Ollama, Hivemind, the MCP server, all
    Vexa services, and the dashboard — runs as supervisord-managed processes inside one
    `kioku-stateful` container.
  </Step>

  <Step title="Verify health">
    ```bash
    docker exec kioku-stateful supervisorctl status
    curl http://localhost:9100/health      # Hivemind
    curl http://localhost:8056/            # Vexa API gateway
    curl http://localhost:18888/health     # MCP server
    curl http://localhost:3001             # Dashboard
    ```

    Every process in `supervisorctl status` should show `RUNNING`.
  </Step>

  <Step title="Install CLI">
    ```bash
    cd ../../services/cli
    cargo install --path crates/cc-cli

    # Bootstrap the first admin account on the local Hivemind server
    export KIOKU_SERVER=http://localhost:9100
    kioku register-admin

    # Later sign-ins can use the same local server default
    kioku signin
    ```
  </Step>
</Steps>

## Services

| Service | Port | Description |
|---------|------|-------------|
| Hivemind API | `9100` | Core API (auth, workspaces, knowledge search) |
| MCP server | `18888` | Unified MCP server (knowledge + meeting tools) |
| Vexa API Gateway | `8056` | Meeting bot API |
| Vexa Admin API | `8001` | Admin operations (internal-only by default) |
| Dashboard | `3001` | Web UI |
| MinIO Console | `9001` | Object storage UI |
| Ollama | `11434` | Local embedding model server |
| Qdrant | `6334` (gRPC) / `6333` (REST) | Vector DB |

## Management

```bash
docker exec kioku-stateful supervisorctl status        # process status
docker exec kioku-stateful supervisorctl tail -f <name>  # tail one process's logs
docker compose -f docker-compose.stateful.yml stop      # stop (data preserved)
docker compose -f docker-compose.stateful.yml down      # stop and remove the container
docker compose -f docker-compose.stateful.yml down -v   # ⚠ also destroys all volumes
```

<Note>
  `scripts/manage.sh`/`scripts/setup.sh`/`scripts/healthcheck.sh` in this directory predate
  the current single-container design and describe separate per-service containers that no
  longer exist — don't rely on them until they're updated. See
  [Docker Compose](/deployment/docker-compose) for more.
</Note>
